# 电商文案生成与素材入库助手

基于 Dify + DeepSeek 的电商文案工作流。输入产品名称（建议附真实功能）和目标人群，生成 3 条商品标题、3 个核心卖点和 1 条短视频脚本开头，并自动新增到飞书多维表格。

## 工作流

```mermaid
flowchart LR
    A[产品名称与目标人群] --> B[DeepSeek 生成文案]
    B --> C[页面输出]
    B --> D[获取飞书访问令牌]
    D --> E[整理并转义 JSON]
    E --> F[新增飞书素材记录]
```

## 文件

- `dify-ecommerce-copywriter.ifpkg`：当前 Dify 导出的应用包格式，已脱敏，可在兼容版本中导入。
- `workflow.yml`：同一工作流的 YAML 配置，方便查看和版本管理。源配置版本为 0.7.0，旧版 Dify 的兼容性未验证。

## 使用方法

1. 在 Dify 工作室导入应用包；按照提示安装 DeepSeek 插件。
2. 在「设置 → 模型供应商」配置自己的 DeepSeek API Key，并保证模型账户有可用额度。API Key 属于供应商凭证，不存储在本项目中。可用 `DEEPSEEK_API_KEY` 作为你自己的密钥配置名称。
3. 在 LLM 节点选择自己账户支持的 DeepSeek 模型。源项目使用 `deepseek-v4-flash`；如不可用，请自行选择可用模型。
4. 在工作流「环境变量」中填写下面四项空值。
5. 新建飞书自建应用，开通应用身份权限 `base:record:create`，并将该应用添加为目标多维表格的可编辑文档应用。
6. 测试生成、核对飞书新增记录后，再发布自己的应用。

| 环境变量 | 用途 |
|---|---|
| `FEISHU_APP_ID` | 飞书自建应用 App ID |
| `FEISHU_APP_SECRET` | 飞书 App Secret，使用 Secret 类型 |
| `FEISHU_BASE_TOKEN` | 多维表格的底层 app/base token；Wiki 链接中的 token 不能直接使用 |
| `FEISHU_TABLE_ID` | 数据表 ID，通常以 tbl 开头 |

## 飞书字段

写入依赖三个文本字段，名称必须一致：`产品名称`、`目标人群`、`生成文案`。每次运行新增一行。主字段可命名为 `素材名称`，使用公式：

```text
IF([产品名称]="","",[产品名称]&"｜"&[目标人群])
```

## 示例输入

- 产品名称：帆布托特包（可放A4文件、带内袋、可折叠）
- 目标人群：每天带书和资料上课的大学生，喜欢简约风格，关注收纳和携带便利

## 已知限制

- 已开启推理标签分离，`text` 用于展示和入库，思考过程不作为文案保存。
- 输出是初稿，需人工核对产品事实、宣传表述和字数，不能把未提供的性能当作真实卖点。
- 运行耗时受模型、网络和内容影响，不保证固定 10 秒完成。
- 飞书 HTTP 节点的“成功”不等于业务成功；排查时检查响应 `code` 是否为 0，并确认表中出现新记录。
- 原在线项目曾完成生成和飞书写入验证；本脱敏模板的导入后联调需使用你自己的凭证完成。

## 凭证处理

本仓库不包含 DeepSeek API Key、飞书 App Secret 或真实 App ID。环境变量值均为空，个人飞书表格标识已替换为变量。请勿将真实密钥、调试日志、运行缓存或 `.env` 提交到公开仓库。
